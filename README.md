# WEPRO — Skin—Clinic store (дипломный проект 2026)

Интернет-магазин по макету Figma «Diploma Project 2026» на чистом **HTML, CSS и JavaScript** (ES-модули, без фреймворков и сборщиков). Все данные приходят с бэкенда учителя — **Sandbox Shop API**.

## Запуск

ES-модули не работают при открытии файла двойным кликом (`file://`), поэтому нужен любой локальный сервер:

- **VS Code → Live Server**: правый клик по `index.html` → *Open with Live Server*;
- или в терминале: `npx http-server -c-1` (либо `python -m http.server`) и открыть показанный адрес.

`npx serve` не подходит: он перенаправляет `product.html?id=…` на `/product` и теряет параметры адреса.

## Страницы

| Файл | Что на странице | Запросы к API |
| --- | --- | --- |
| `index.html` | Hero, Best sellers, Shop by category, Featured products | `GET /products/bestsellers`, `GET /categories`, `GET /products/newest` |
| `products.html` | Каталог: фильтр по категориям и цене, пагинация | `GET /products?category=&minPrice=&maxPrice=&page=&limit=12`, `GET /categories`, `GET /products?limit=100` (верхняя граница ползунка цены) |
| `product.html?id=…` | Товар, количество, «Add to cart», отзывы, «Leave a comment» | `GET /products/:id`, `POST /cart`, `POST /products/:id/comments` |
| `cart.html` | Корзина, изменение количества, удаление, оформление заказа | `GET /cart`, `PATCH /cart/:productId`, `DELETE /cart/:productId`, `POST /orders` (гость — `GET /products/:id` для актуальных цен) |
| `login.html`, `register.html` | Вход и регистрация | `POST /login`, `POST /register`, `POST /cart` (перенос корзины гостя) |
| `profile.html` | Профиль, выход, «My orders» | `GET /me`, `POST /logout`, `GET /orders` |

На каждой странице шапка показывает «Bag (N)»: у вошедшего пользователя число берётся из `GET /cart`, у гостя — из корзины в браузере.

Адрес API задаётся в одном месте — `js/config.js` (`API_BASE`).

## Корзина без входа

Гость может класть товары в корзину, менять количество и удалять их без авторизации — корзина гостя хранится в браузере (`js/guest-cart.js`), а названия, цены и фото при открытии корзины обновляются из API. Вход нужен только для оформления: «Go to checkout» ведёт на страницу входа или регистрации, после входа товары гостя переносятся в корзину аккаунта (`POST /cart`) и пользователь возвращается в корзину, где оформляет заказ. Если сервер временно не ответил, товары остаются в браузере и переносятся при следующем открытии корзины; если товар не прошёл по лимитам API, корзина показывает, какие товары не удалось добавить.

## Структура

```
assets/images   фото и логотип, экспортированы из Figma
assets/icons    SVG-спрайт иконок и логотип Skin—Clinic из Figma
assets/fonts    Inter 3.19 и SF Pro Display (woff2)
css/            base → layout → components → pages/<страница>.css

                layout.js (шапка), ui.js, modal.js, forms.js, utils.js, boot.js (проверки до загрузки модулей)
js/pages/       скрипт для каждой страницы
```

## Адаптив

Вёрстка по двум макетам: desktop **1920px** и mobile **390px**. Между ними сетки перестраиваются (4 → 3 → 2 колонки), мобильная версия включается до 767px.

## Безопасность

- Заголовки безопасности задаются в `_headers` (Netlify): Content-Security-Policy (скрипты, стили и шрифты только с сайта, запросы только к `api.wepro.uz`, запрет встраивания во фрейм), `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`. Локальные серверы (Live Server) эти заголовки не отправляют, поэтому их скрипт автообновления работает без ошибок в консоли.
- Все данные с сервера экранируются перед вставкой в HTML (защита от XSS).
- Переход после входа (`?next=`) разрешён только на страницы этого сайта.
- Токен хранится в `localStorage`; при ответе 401 сессия очищается, `Log out` делает все токены недействительными на сервере.
- Изменение количества в корзине отправляется с задержкой, чтобы не упираться в лимит API (120 запросов в минуту).

## Отличия от макета (сделаны намеренно)

- **Вход по Email**, а не по телефону: `POST /login` принимает только `email` и `password`.
- Под формами добавлены ссылки «Register» / «Log In» — в макете перехода между ними нет.
- На кнопке регистрации оставлен текст из макета («Log In»).
- В мобильной регистрации все 6 полей (в мобильном макете только 2), в мобильном профиле есть «My orders».
- Под каталогом — пагинация (в API 32 товара, на странице 12), шкала цены строится по самому дорогому товару.
- Мобильная пустая корзина показывает строки Subtotal / Discount, как в мобильном макете; в остальных состояниях — только Total.
- Футер: пункты колонок Products, Support, Company, строка Terms of service / Privacy policy / Cookies settings и иконки соцсетей — без ссылок. В макете у них нет ни страниц, ни переходов, поэтому это обычный текст и иконки, а не ссылки-заглушки на `#`.

## Шрифты

Подключены из `assets/fonts` (без Google Fonts): **Inter 3.19** — та же версия, что использует Figma (ширины надписей совпадают с макетом), и **SF Pro Display** 400/600 — файлы от учителя. Satoshi (мобильные отзывы) берётся из системы, если установлен; иначе показывается Inter с подогнанной шириной.
